日報「合計金額だけ入力」モードの新設

OCR が失敗した日でも日報を残せるようにする。ついでに死んでいる Gemini 貼付経路を撤去する。
spec: docs/superpowers/specs/2026-07-15-summary-only-input-design.md

  1. 入力を「明細あり / 合計のみ」の 2 タブにする。合計のみは売上（税込）1項目だけ。
  2. Gemini テキスト貼付 UI を input.html から撤去し、その場所を合計入力に置き換える。
  3. 給与計算は合計のみの日も含める。時間帯グラフは自然に対象外。グループ共有は影響ゼロ（調査で確認済み）。

なぜ必要か

日報は Firebase Functions の OCR（PP-OCRv5）で画像から取り込む。撮影条件やサーバーエラーで読めない日がある。ところが input.html:565 に if (!parsed) return alert(...) のガードがあり、明細が無い日報を保存する手段が一切ない。結果、OCR が失敗した日は日報そのものが残らず、給与計算に穴が空く。

現状の 3 経路のうち、生きているのは 1 つだけ ① 画像OCR = 動く／② Gemini テキスト貼付 = 実質使われていない（外部AIに画像を送る自己責任フロー）／③ 手入力 = そもそも導線が無い（「行を追加」ボタンすら存在しない）

データモデル

Firestore drives/{userId}/daily/{日付} に 2 フィールドを足すだけ。

フィールド型説明
_summaryOnlybooleantrue = 合計のみレコード。明細ありには付けない
totalSalesnumber税込の売上合計。_summaryOnly のときだけ意味を持つ
{
  date: '2026-07-15',
  _summaryOnly: true,
  totalSales: 52300,   // 税込
  trips: [], rests: [],
  // 以下は既存どおり（乗務種別・出庫・帰庫・総走行距離・メモ・違反…）
}
不採用にした案：合計額を持つダミー trip を 1 行入れる 乗車回数が 1 と数えられ、時刻も場所も無い trip が全グラフに混入する。trips.length を数えている箇所（index.html:973, detail.html:136 ほか）を全部直す羽目になるので却下。

下流扱い改修
給与計算 payroll.js含める（totalSales を読む分岐を追加）要
月間売上・日別ヒートマップ含める（calcDailySales 経由で自動追従）不要
時間帯 / エリア / km 系グラフ対象外（明細ゼロなので何も出ない）不要
客単価・時給などの平均分母から除外（0除算で平均を壊さない）要
AI コーチ coach/*分析対象外要
グループ共有プール影響なし不要
detail / index 画面「合計のみ」バッジ表示要
グループ共有が影響ゼロな理由（コードで確認済み・確度100%） buildGroupPool（group-pool-core.js:56）が出すのは heatmap（曜日×時刻の時給中央値）と areas（降車エリア）だけで、日合計売上は出力していない（コメント :55「合計は出力に残さない」）。さらに peerMedianHourlyDow は workingMin > 0 のセルしか積まないので、明細ゼロの日報はプールに 1 セルも足さない。他メンバーの中央値を汚さない。
眠っていた受け皿が再稼働する chart-helpers.js:96 に isSummaryOnly(drive) が既にあるが、判定に使う _importedFrom / _periodCount を書き込むコードは現存しない（過去のスプレッドシート移行の名残）。今回 _summaryOnly を足すことで、この関数と呼び出し側 5 箇所が正式に機能を取り戻す。

上書き保護

保存時に同日付の既存レコードを見て、モードが変わる上書きのときだけ確認を出す。同種別の上書きは今までどおり無言。

既存今から保存挙動
なしどちらでも無言で保存
明細あり明細あり無言で上書き（現状どおり）
合計のみ合計のみ無言で上書き
合計のみ明細あり確認「合計のみで登録済みです。明細で上書きしますか？」
明細あり合計のみ確認「明細が消えます。本当に上書きしますか？」← 本命のガード

Gemini 貼付の撤去（依存確認済み）

  • OCR 取り込み経路（applyOcrImport, input.html:281）は sessionStorage の構造化データを直接使う → parser.js に依存しない
  • 既存レコードの編集経路（:255）も同様に独立
  • js/parser.js は admin.html / bulk-input.html がまだ使う → ファイルは残す。input.html の import を外すだけ
  • rawText は「既存値を引き継ぐ、新規は空文字」に変更 → 過去レコードの rawText を消さない

要点。OCR 失敗時に日報が「1件も残せない」のが今の最大の穴で、これを塞ぐのに必要なのは新フィールド 2 つと保存ガードの分岐だけです。グループ共有は調査の結果まったく触らずに済み、isSummaryOnly という受け皿も既に半分できていました。

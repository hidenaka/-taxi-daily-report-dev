「GPSの座標は考慮されているのか」というご質問の答えです。結論から言うと、 座標は町名を1回引くためだけに使われ、その後は一切使われていません。 調べる途中で住所のバグも1つ見つけたので、そちらは直しました。

3行でいうと

  1. GPSの緯度・経度は「いま何町にいるか」を知るためだけに1回使い、その場で捨てている。地図の距離は一切見ていない。
  2. 「近所かどうか」は実際に走った実績（降ろしてから25分以内に次を乗せた町の組み合わせ）で決めている。これは理にかなっているが、実績のない町では手も足も出ない。
  3. そのとき使う「似た名前の町を探す」処理を測ったら、あてずっぽうと同じ精度（15%）だった。ここに座標を足すかどうかを決めてほしい。

「近隣＝実際に走った実績」という決め方自体は理にかなっています。 地図の直線距離だと、川の向こう・高速の反対側・一方通行の先など「近いのに行けない町」が近所に入ってしまいます。実績ベースならそれが自動的に外れます。実データで港区赤坂の近所を出すと、六本木・南青山・虎ノ門・麻布十番…と、実感どおりの並びになりました。

5決めてほしいこと

座標を入れるかどうか。A / B / C から選んでください。

A：今のまま（実績だけで判断）追加作業なし

座標は入れない。今日直した全角バグと、先に直した「条件を自動で広げる」修正だけを出す。

  • 👍 実際に走れる町だけが近所として残る良さは、そのまま保たれる
  • 👎 初めての町・実績の薄い町では、これまでどおり的外れな起点が選ばれる（15%）

B：迷子のときだけ座標で助ける★ おすすめ

ふだんの近所判定は今までどおり実績ベース。「GPSの町名が過去データに無かったとき」だけ、 町の代表地点の座標を使って、本当に近い町を起点にする。

  • 👍 実績ベースの良さを一切壊さず、いちばん外している所だけを直せる
  • 👍 町名→座標の表は公開データ（すでに住所辞書で使っている出どころ）から作れる。東京23区＋周辺で数百KB程度
  • 👍 お客さんの居場所を記録するわけではない。町の代表地点の一覧をアプリに同梱するだけ
  • ⚙️ 作業量は中くらい（辞書づくり＋起点えらびの差し替え＋テスト）

C：近所の判定を全部、距離に置き換える非推奨

「25分以内に行き来した実績」をやめて、「半径◯km以内」で近所を決める。

  • 👍 実績ゼロの町でも必ず近所が出る
  • 👎 川の向こう・高速の反対側など「近いのに行けない町」が近所に混ざる
  • 👎 いま実感どおりに出ている赤坂→六本木・虎ノ門といった並びが崩れる

おすすめはBです。理由は、今の実績ベースが「実際に走れる関係だけを残す」という点で 距離より優れており、壊すべきではないから。座標は、その実績が無くて困っている一点だけに足すのが一番効きます。

# カウントダウン休憩タイマー 設計（Phase 1）

- 日付: 2026-06-05
- 対象: `tools/index.html`（乗務タイマー）
- 状態: 設計確定待ち → 実装

## 1. 背景・目的

現状の乗務タイマーは「休憩を**カウントアップ**で計測し、『記録』ボタンで合計休憩に加算、連続走行可能時刻を逆算する」休憩管理ツール。

乗務員は「あと何分休めるか」を**目標時間から逆算（カウントダウン）**で見たい。例：27分の休憩を取る → 残り時間が減っていくのを見ながら休む → 途中で切り上げても、実際に休んだ分が正しく記録される。

本 spec は **Phase 1（カウントダウン表示モード＋前面通知＋画面常時点灯）** を扱う。
**Phase 2（裏で動いている時のサーバー Web Push 通知）は別 spec / 別リリース**として後続で行う（§8 に概要のみ記載）。

## 2. 核心設計：内部ストップウォッチは温存

**最重要原則：記録・合計休憩・残り必要休憩・連続走行可能時刻の逆算ロジックは一切変更しない。**

- 内部状態 `state.stopwatch` は今と同じく「実経過時間（elapsedMs / startedAt）」を持つ
- `記録`ボタンが保存するのは**常に実経過時間**（`currentStopwatchMs()`）
- カウントダウンは「**残り = 目標 − 実経過**」という**表示変換**と、「0をまたいだ通知」だけを足す

帰結：
- 「27分セット → 途中で止める」→ 実際に休んだ経過時間（例 18分）がそのまま記録される。**“途中で止めてもカウントが狂わない” が自動的に成立**する。
- 0を超えて休み続ければ、実経過（例 31分）が記録される。

## 3. UI 変更（`tools/index.html` の `.stopwatch` セクション内）

### 3.1 モード切替（セグメントコントロール）
ストップウォッチ表示の上に2択トグルを追加：

```
[ カウントアップ | カウントダウン ]
```

- 既定は `カウントアップ`（＝現行と同じ挙動）
- 走行中（running）でも切替可。切替は表示の見せ方を変えるだけで内部経過には影響しない

### 3.2 目標設定行（カウントダウン選択時のみ表示）
```
目標: [11] [15] [27] [30] [45] [60] 分   ｜  自由入力 [  ]時[  ]分
```
- プリセット chip：`11 / 15 / 27 / 30 / 45 / 60` 分（タップで `countdownTargetMin` を設定、選択中をハイライト）
- 自由入力：時・分の number 入力（既存設定行と同じ `hm-input` スタイル）
- スタート前でもスタート後でも目標を変更できる（変更は残り表示に即反映、実経過は不変）

### 3.3 メイン表示
- **カウントアップ時**：従来どおり実経過を `HH:MM:SS` で表示
- **カウントダウン時**：
  - 残り時間（`target − elapsed`）を表示。`< 1時間` は `MM:SS`、`≥ 1時間` は `HH:MM:SS`
  - 0以下になったら表示クラスを `over`（赤）に切替え、`超過 +MM:SS` の形で経過超過分を表示し続ける
- 既存の「暫定休憩」行（記録済み + 現在）は両モードとも従来どおり表示（＝記録される分が見える）

### 3.4 ボタン
- `スタート / 記録 / 破棄` は現行のまま。`記録`の有効化条件（実経過 ≥ `breakCountMin`）も不変
  - 補足：5分など `breakCountMin`（既定11分）未満の目標を設定しても、実経過が11分に満たなければ`記録`は押せない（＝法定休憩としてカウントできないため。現行仕様を踏襲）

### 3.5 「画面を消さない」トグル（Wake Lock）
- カウントダウン目標設定行の近くにチェックボックス：`☐ 休憩中は画面を消さない`
- ON かつ スタート中：`navigator.wakeLock.request('screen')` で画面常時点灯
- OFF・記録・破棄・リセット・ページ非表示（`visibilitychange`）時：wakeLock を解放
- 既定 OFF（バッテリー消費・車内のまぶしさを本人が選ぶ）
- 非対応ブラウザ（iOS16.4未満等）：トグルは出すが、`wakeLock` 未定義なら no-op（チェックしても何も起きない／ラベルに「対応端末のみ」補足）

## 4. 0到達時の通知（前面＝画面表示中のみ）

ライブで残り時間が `> 0` → `≤ 0` を**またいだ瞬間に1回だけ**：

1. **音**：Web Audio API でビープ（短音×2程度）。`AudioContext` は `スタート`タップ時に生成/`resume()` して iOS の自動再生制限を解除しておく
2. **バイブ**：`navigator.vibrate([200,100,200])`（Android のみ実効。iOS は非対応で no-op）
3. **視覚**：`deadline-card` ではなくストップウォッチ表示を一時的に赤フラッシュ（CSS アニメ）＋ `over` クラス維持

通知は「1回だけ」：ランタイムフラグ `countdownNotified` で管理。
- ページ再読込時、ロード時点で既に `elapsed > target`（running）なら `countdownNotified = true` に初期化し、再読込で鳴らさない（ライブのクロスのみ鳴らす）

### ⚠️ 既知の制約（Phase 1 の範囲）
**画面ロック／アプリを裏に回すと iOS は JS タイマーを凍結するため、その間に 0 を迎えても音は鳴らない**（鳴るのは画面を開いている時）。Wake Lock ON ならロックを防げるが、本人が手動でロックすれば同様に止まる。ロック中でも確実に鳴らす要件は **Phase 2（Web Push）** で対応する。

## 5. データモデル（localStorage `taxi-timer-v1`）

既存スキーマに**2項目だけ追加**。既存フィールドは無変更。

| フィールド | 型 | 既定 | 説明 |
|---|---|---|---|
| `mode` | `'up' \| 'down'` | `'up'` | 表示モード |
| `countdownTargetMin` | number | `27` | カウントダウン目標（分） |

- `wakeLockOn`（Wake Lock トグルの状態）も同様に永続化（既定 `false`）
- 後方互換：旧データに `mode` 無し → `'up'` 扱い。`loadState()` の defaults とバリデーションに追加
- `saveState()` に新フィールドの書き出しを追加

## 6. 実装方針（純粋関数中心）

新規ロジックは副作用のない純粋関数として実装し、`renderStopwatch()` から使う：

- `fmtCountdown(remainingMs) -> string`：残りを `MM:SS` / `HH:MM:SS`、負なら `超過 +…` を返す
- `computeRemainingMs(elapsedMs, targetMin) -> number`：`targetMin*60000 - elapsedMs`
- 0クロス検出：直前 tick の remaining 符号を保持し、`prev > 0 && now <= 0` で発火

`renderStopwatch()` / `renderButtons()` を `mode` 分岐に対応させる。`renderMetrics()` 以降（休憩集計・deadline）は**触らない**。

## 7. テスト

- 純粋関数（`fmtCountdown` / `computeRemainingMs` / 0クロス判定）はユニットテスト可能な形で実装
- dev 反映後、**kimi-webbridge（実ブラウザ＝実アカウント）**で手動スモーク：
  1. カウントダウンに切替 → 27分プリセット → スタート → 残りが減る
  2. 途中で `記録` → 実経過分（目標未満）が合計休憩に正しく加算される
  3. 0クロスで音・赤フラッシュ・超過カウント継続
  4. モード往復（up↔down）で内部経過が保たれる
  5. リロードで mode/target/running が復元、再読込で誤発火しない
  6. Wake Lock トグル ON でスタート → 画面が消えない（対応端末）
- SW キャッシュ：`tools/index.html` 自体は素通しだが、新規 JS/CSS を別ファイル化する場合は `sw.js` の `CACHE_NAME` を bump（今回はインライン追記想定なので不要見込み。確定時に確認）

## 8. Phase 2 概要（本 spec の範囲外・後続）

裏で動いている時のロック画面通知 = **サーバー Web Push**。
- フロント：通知許可リクエスト → Push 購読（VAPID）→ スタート時に `{subscription, targetTimestamp}` を Worker に送信
- Worker（Cloudflare）：購読保存 + Durable Object `alarm()` を target に設定 → 発火時に Web Push 送信
- Service Worker：`push` 受信 → `showNotification()` でロック画面に通知
- 途中停止：予約済み通知のキャンセル API を呼ぶ
- iOS 前提：ホーム画面追加済み・iOS16.4+・通知許可。別 spec で詳細設計する。

## 9. スコープ外（YAGNI）

- ロック中でも鳴る通知（→ Phase 2）
- 複数同時タイマー
- カウントダウン専用の履歴（記録は既存の休憩履歴に統合）

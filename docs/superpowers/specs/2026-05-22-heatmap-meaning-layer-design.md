# 効率ヒートマップ「意味レイヤー」設計（稼ぎ時/休憩向きラベル + 安定度）

**作成日**: 2026-05-22
**対象**: タクシー日報PWA（cabis）— `review.html` / `support.html` の効率ヒートマップ
**関連仕様**: `2026-04-27-recovery-and-heatmap-design.md`（ヒートマップ¥/h一本化・全員統合タブ）、`2026-05-07-vehicle-type-filter-design.md`（車種フィルタ）
**位置づけ**: オンボーディング改善 3分割のうち「塊①」。塊②（お手本導線・ゲート判断）/塊③（入力画面オンボーディング）は別仕様。

---

## 1. 背景

### 1.1 きっかけ
知人ユーザーから「分析画面がリッチで良いが、どれをどのように見ればいいかわからない」というフィードバック。特に**新人ドライバーが一番知りたい「いつ走って・いつ休むか」に、今の画面が答えていない**ことが判明した。

### 1.2 詰まりの正体（現状コード確認済み）
効率ヒートマップ（曜日×時間帯の¥/h）は実装済みだが、表示されるのは**¥/hの数字と高低のグラデーション色だけ**。

- **「どのように見るか」が欠けている**: セルの数字が「稼ぎ時なのか・休憩向きなのか」という*意味*に翻訳されていない。新人は数字の羅列を解釈できない。
- **平均しか出ない**: セルは期間平均の¥/h。その時間帯が「安定して稼げる」のか「日によってムラが大きい」のかが見えない。休憩の判断材料に欠ける。

### 1.3 「集約基盤は既にある」前提（重要な確認結果）
現状コード調査で、以下は**すべて実装済み**と確認した。本仕様では新規構築しない:

| 機能 | 現状 | 実体 |
|---|---|---|
| 全員統合（他ユーザー集計） | ✅ | `support.html` / `getAllUsersDrivesForMonth` |
| 車種別フィルタ（JT/プレ） | ✅ | `vehicle-filter.js` / 全員統合×車種も可能 |
| データ提供オプトイン | ✅ | ベンチマーク参加フラグ |
| 段階制限（営業日数ベース） | ✅ | `aggregate-access.js` 4段階 |
| サンプル<3日のグレー表示 | ✅ | support.html `low-sample` |

→ 本仕様（塊①）が足すのは**「意味レイヤー」2つだけ**: ①稼ぎ時/休憩向きラベル ②安定度/ムラ。これは自分データにも全員×車種お手本にも等しく効く。

---

## 2. ゴール

1. ヒートマップの各セルを「稼ぎ時 / 普通 / 休憩向き」に**意味づけ**し、新人が一目で「いつ走るか・いつ休むか」を読めるようにする。
2. 各時間帯が**安定して稼げるか / ムラが大きいか**を表示し、休憩タイミングの判断材料を増やす。
3. ヒートマップに**常設ガイド（凡例＋使い方1行）**を置き、中野さんの個別解説なしで読めるようにする。
4. 上記を `review.html`（自分データ）と `support.html`（自分/全員×車種）の**両方**に入れる。

| 区分 | スコープ内 | スコープ外 |

## 4. 設計

### 4.1 全体方針：共通ヘルパーで両ページに効かせる

review.html と support.html はセル粒度が異なる:
- **review.html**: `dowZoneEfficiency(drives, zones)`（chart-helpers.js:213-244）でゾーン単位（human/shift プリセット、4〜5ゾーン）。描画は `renderHeatmap()`（review.html:594-649）。
- **support.html**: `hourlyDowEfficiency(drives)`（chart-helpers.js:581-654）で1時間単位。描画は `renderHourEff()`（support.html:1053-1109）。

→ 粒度に依存しない**共通の意味付けヘルパー**を `chart-helpers.js` に新設し、両描画関数から呼ぶ。

```
classifyCells(cells) → 各 cell に { tier: 'earn'|'normal'|'rest', stability: 'stable'|'mid'|'volatile'|'insufficient' } を付与
```
- 入力 `cells`: 各セルが `{ hourlyValue:number, days:number, dailyValues:number[] }` を持つ配列（粒度はゾーンでも時間でも可）
- `dailyValues`: そのセルの**日別¥/h**の配列（安定度計算に必須）

### 4.2 稼ぎ時/休憩向きラベル（相対判定）

**定義**: 「いま表示中のデータセット」（そのページ・タブ・車種フィルタ適用後の matrix）の**有効セル（days≥3）の¥/h分布**で相対判定する。

- **稼ぎ時 (earn)**: ¥/h が有効セル中の上位1/3
- **休憩向き (rest)**: ¥/h が有効セル中の下位1/3
- **普通 (normal)**: 中間1/3
- **データ不足 (insufficient)**: days<3 → ラベルなし（既存グレー継続）

**なぜ相対か**: 絶対閾値（例 ¥3000/h以上=稼ぎ時）だと、全体水準の低い新人は全セルが「休憩向き」になり無意味。相対なら「自分（またはお手本）の中で相対的にどこが稼ぎ時か」が常に出る。お手本（全員×車種）に切り替えれば「ベテラン集団の中での稼ぎ時」が見える。

> **オープン論点A（レビュー要）**: 3段階（earn/normal/rest）か、median基準の2段階（median以上=稼ぎ時/未満=休憩向き）か。推奨は3段階（「普通」を挟むことで誤誘導が減る）。

**「休憩向き」の意味づけ注記**: 「休憩向き＝相対的に稼ぎにくい時間。休憩や、次の稼ぎ時に向けた仕込み・移動に向く」とガイドで明示し、「何もするな」と誤読されないようにする。

### 4.3 安定度/ムラ

**定義**: 各セルの**日別¥/hのばらつき** = 変動係数 CV（標準偏差 ÷ 平均）。

| 表示 | 条件 | 意味 |
|---|---|---|
| ◎ 安定 (stable) | CV ≤ 0.3 | 安定して稼げる/稼げない時間 |
| ○ 中 (mid) | 0.3 < CV ≤ 0.6 | ややムラあり |
| △ ムラ (volatile) | CV > 0.6 | 日によって大きく変動 |
| − (insufficient) | days < 3 | 判定不可 |

> **オープン論点B（レビュー要）**: CV閾値（0.3 / 0.6）は暫定。実データで「体感のムラ」と合うか校正が必要。リリース後にデータで調整する前提。

**実装上の肝**: 現状 `hourlyDowEfficiency` / `dowZoneEfficiency` はセル内で sales・workingMin を**合算してから**¥/hを出している。安定度には**日別¥/hの配列**が必要なので、両関数を拡張し、セルごとに日別の `{ sales, workingMin }`（または日別¥/h）を保持して返す。戻り値の既存フィールドは維持し、`dailyValues` を追加する後方互換拡張とする。

### 4.4 セルの見せ方（情報過多を避ける）

セルは狭いため、本体には主役情報だけ、詳細はtapに逃がす。

- **セル本体**: 既存の色グラデ（高低）に加え、**ラベルの記号/縁取り**を最小限。
  - 稼ぎ時=濃い暖色＋小マーカー、休憩向き=寒色系、普通=中間（既存色スケールを意味に合わせて再マッピング）。
  - 安定度は本体では小さく（例: セル隅に ◎/○/△ の極小バッジ）。視認性が崩れるなら本体では省き、tap詳細に集約。
- **セルtap詳細（既存機能を拡張）**: 「曜日×時間帯／ N日／ 平均¥/h／ レンジ（最小〜最大）／ 安定度（◎○△）／ 区分（稼ぎ時/普通/休憩向き）」。

> **オープン論点C（レビュー要）**: 安定度をセル本体に出すか、tap詳細だけにするか。狭いモバイル画面での視認性次第。実装時にモックで判断。

### 4.5 常設ガイド（凡例＋使い方）

各ヒートマップ直上に常設の凡例＋使い方1行を置く（中野さんが選んだ「常設ガイド化」）。

例:
> **色が濃い＝稼ぎ時／青っぽい＝休憩向き。◎は安定、△は日によってムラ。グレーは記録がまだ少ない時間。**
> 👉 休憩は「休憩向き」の時間に取ると、稼ぎ時を逃しません。

- 自分タブ/全員（お手本）タブで文言を僅かに出し分け（お手本時は「みんなの傾向です」を補足）。

## 5. テスト戦略

### 5.1 ユニットテスト（`tests/chart-helpers.test.js` に追加）
- `classifyCells`:
  - 有効セルの相対1/3区切りが正しい（境界値含む）
  - days<3 が insufficient になりラベル分布の母数から除外される
  - CV 計算（既知の日別配列→期待CV、閾値での tier 切替）
- `hourlyDowEfficiency` / `dowZoneEfficiency` 拡張:
  - `dailyValues`（日別¥/h）が正しく集計される（複数日×複数drive横断）
  - 既存フィールド（hourlyA, days 等）が回帰しない

### 5.2 統合動作確認（手動・実機）
1. review.html: ヒートマップに稼ぎ時/休憩向きラベル＋安定度が出る。車種タブ切替で再判定される。
2. support.html: 「自分のみ」「全員統合」両タブでラベル/安定度が出る。全員×車種でお手本として読める。
3. days<3 のセルがグレー＆ラベルなしで維持される（既存挙動を壊さない）。
4. セルtapで N/平均/レンジ/安定度/区分が出る。

## 6. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 関数拡張で既存ヒートマップ数値が変わる | 既存ユーザーの体感ズレ | `dailyValues` は追加のみ・既存フィールド不変。回帰テスト必須 |
| 相対判定が少データで荒れる | 新人の自分タブで誤誘導 | days≥3 のみ母数化。お手本（全員×車種）で補う前提を凡例に明示 |
| セルに情報詰め込みすぎ | かえって読みにくい | 本体は色＋ラベル中心、安定度・詳細はtapに逃がす（論点C） |
| CV閾値が体感と合わない | 安定/ムラの判定が外れる | 閾値は暫定、リリース後に実データ校正（論点B） |
| 2ページ同時改修で影響範囲拡大 | デグレ範囲が広い | 共通ヘルパーに集約しテストで担保。dev→承認→本番の順守 |

## 8. オープン論点（レビューで決める）

- **論点A**: ラベルは3段階（earn/normal/rest）か median 2段階か。推奨=3段階。
- **論点B**: 安定度CV閾値（0.3/0.6）。暫定値、実データ校正前提。
- **論点C**: 安定度をセル本体に出すか tap詳細のみか（モバイル視認性）。
- **論点D（IA）**: 「どれを見ればいい」への対処として、review.html の初期表示でヒートマップを上位に置き、他セクションを折りたたむか。**既存ユーザー（知人）はリッチさを好む**ため、やるなら「折りたたみ＋展開状態を記憶」。本仕様の主スコープ外とし、塊③（オンボーディング）で扱う候補。

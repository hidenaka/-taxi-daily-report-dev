# 空港定額運賃マップ ツール 設計書

- **基準**: dev/main @ `a817026f3`、本番確認日 2026-05-29（`app.taxicabis.com/tools/arrivals.html`）
- **ブランチ**: `feat/airport-fixed-fare-map`（dev clone `~/work/taxi-dev`、origin=dev）
- **目的**: 到着便ページから飛べる、羽田・成田の定額運賃を「地図タッチ or 検索」で感覚的に確認できるツール

## 1. 概要 / ユースケース

空港で客付けする乗務員が、行き先の区を地図でタッチ（または区名で検索）すると、その区への**羽田・成田の定額運賃（昼／深夜）**が即座に出る。高速代の概算やメーター概算は出さない（定額の確認に特化）。

## 2. スコープ（カバーするエリア = 25）

東京23区 + 武蔵野市 + 三鷹市。

千代田・中央・港・新宿・文京・台東・墨田・江東・品川・目黒・大田・世田谷・渋谷・中野・杉並・豊島・北・荒川・板橋・練馬・足立・葛飾・江戸川（23区）＋ 武蔵野市・三鷹市。

範囲外（埼玉/千葉/神奈川/多摩の他市町村）は今回対象外。将来拡張余地として data 構造だけ拡張可能にしておく。

## 3. 表示する料金（タッチ結果の中身）

各エリアにつき定額4種：

| | 羽田 | 成田 |
|---|---|---|
| 定額（昼） | ¥X | ¥Y |
| 定額（深夜割増 22:00〜翌5:00） | ¥X' | ¥Y' |

- **メーター概算・高速代は出さない**。理由：高速代はルート・時間帯で変わり定額に乗らない。
- カードに一行注記：「※定額に高速代は含みません（別途）」。
- 深夜割増の時間帯：22:00〜翌5:00。
- **今が深夜帯なら深夜行を自動ハイライト＋「今は深夜料金」バッジ**（端末時刻で判定）。
- 定額は区⇄空港で同額（往復同じ）。到着便文脈では空港→区の客付けで使う。
- 欠損時（ある空港の定額が未設定/未確認のエリア）は「—」表示＋注記。

## 4. 地図（様式化SVG）

- **精密な区境は不要**。「ざっくりの位置関係」で、見て「この辺だな→ボタン一つで確認」できればよい（ユーザー確定要件）。
- 23区を地理的に大まかな配置で並べ、武蔵野市・三鷹市は**その西側に地理通り**配置。
- 各エリア = タップ可能な領域（SVG `<path>`/`<g>`、`data-area` 属性でキー保持）。
- タップで選択ハイライト → 下に料金カード。
- **オフライン完結・APIキー不要・軽量**（静的SVGをHTMLに内包。地図タイル/Leafletは使わない。※`vendor/leaflet` は存在するが本ツールでは不使用）。
- 縦長スマホで横幅にフィット。武蔵野・三鷹が西端に小さく出る配置を許容。

## 5. 検索（地図と二刀流）

- **25エリアの区名サジェスト検索**（`<datalist>`、IC判定の自由入力と同作法）。
- 例「しぶ」→「渋谷区」。地図タップと**完全に同じ着地点**（同じ料金カード）。
- 任意住所のジオコーディングは行わない（オフライン前提と相性が悪く、行き先は必ず25のどれかに属するため不要）。

## 8. データ仕様

```jsonc
{
  "_source_haneda": "<公式定額運賃表URL>",
  "_source_narita": "<公式定額運賃表URL>",
  "_acquired": "2026-05-XX",
  "_note": "定額に高速代は含まず（別途実費）。深夜割増 22:00-翌5:00。",
  "areas": [
    {
      "key": "shibuya", "name": "渋谷区",
      "haneda": { "day": 6900, "night": 8100 },
      "narita": { "day": 24000, "night": 28600 }
    }
    // ... 25件。値は公式表をWeb調査して投入、出典併記。未確認は null → 画面「—」。
  ]
}
```

- 成田の23区は公式でゾーン束ね（同額が複数区に並ぶ）になる場合があるが、データはエリア単位で持ち、同額を許容。
- 値は**公式の定額運賃表をWeb調査**して投入。出典URL・取得日を必ず併記し、区分・金額を検証。確度の低い値は null（「—」表示）。

## 9. アクセス制御・オフライン・デプロイ

- ページ冒頭で `enforceAccess('core', { redirect: '../subscribe.html' })`（他 tools ページと同じ課金ゲート）。
- 新規 HTML/JS/CSS/JSON 追加につき `sw.js` の `CACHE_NAME` を bump、リリース後 PWA 再起動を案内。
- dev反映 = `!~/work/taxi-dev/dpush.sh [worktree dir]`（行頭 `!`、Claude は push しない）。本番 = タグ。
- iCloud `タクシー日報` 本体は触らない。

## 10. エラー処理

- JSON 読込失敗 → エラーバナー表示（arrivals の `#arrivals-error` 同等パターン）。
- 未知エリア／欠損料金 → カードで「—」＋注記。

## 11. テスト

- `airport-fare-data`: エリア検索（部分一致）、料金ルックアップ、データ整合（25件・各4値の型）。
- 深夜判定: 21:59/22:00/04:59/05:00 の境界。
- カード描画: 深夜帯で深夜行ハイライト、欠損で「—」。
- スモーク: `enforceAccess` seed（localStorage `taxi_user_id` + sessionStorage `taxi_sub_cache_v1`）でヘッドレス描画確認。

## 12. 確度の低い点（実装中に要検証）

- 公式定額表の区分・金額（昼/深夜）の最新性。各社で差がある場合は最新の公式（タクシー協会/各社）に統一し出典併記。
- 成田23区のゾーン束ねの正確な区分。
- 高速代「別途」前提の最新確認（込みの定額商品が併存する場合は注記で明示）。

## 13. 非対象（YAGNI）

- メーター概算・高速代概算（IC判定ツールの領分）。
- 任意住所ジオコーディング。
- 25エリア外の市町村。
- 地図タイル/Leaflet 利用。

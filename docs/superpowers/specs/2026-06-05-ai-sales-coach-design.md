## 1. 目的・背景

既存の分析（時給ヒートマップ・エリア統計）は「過去の傾向の提示」止まりで、ユーザーが自分で解釈する必要がある。これを **「目標と現在地と進捗を踏まえて、再現性のある次の動き方を相談できる対話型AIコーチ」** に昇華し、一般分析を個別レコメンドへ変える。明確な差別化機能。

ベテランには「自分のスタイルに加えて、違うやり方も試したくなる張り」を、新人〜中堅には「勝ち筋の再現方法」を提供する。

## 2. 確定した骨組み（ユーザーと合意済み）

| 項目 | 決定 |
|---|---|
| ヒーロー体験 | いつでも押せる「相談」対話型コーチ（オンデマンド・チャット） |
| 目標連動 | 出庫時に今日の目標（¥ or 帰宅時刻）を1タップ設定。会話中の発話で上書き可 |
| 他者データ範囲 | Cabis全体の匿名プール。車種（vehicleType）× エリア × 時間帯で集計。k匿名 ≥2 |
| アーキテクチャ | 検索＋LLM（grounded）。**数字は既存ロジックが計算し、LLMは語りだけ** |
| モデル | プロバイダ非依存のadapter設計。後でGemini Flash / Claude Haiku等から選択 |
| 出力ルール | 必ず「なぜそう動くと再現できるか（根拠）」をセットで返す |

## 3. 体験フロー

1. **出庫時**: 今日の目標を1タップ設定（例: ¥30,000 / または 19時帰宅）。スキップ可（その場合は月目標から日割り推定）。
2. **走行中いつでも**: 「相談」ボタン押下 → 現在地（GPS→町名・**保存しない**）＋現在時刻＋目標進捗を自動取得。
3. **質問**: プリセットチップ（「あと◯円どう動く」「早く帰りたい」「今の場所どう」）＋自由入力。
4. **AI応答**: 具体的な次の動き ＋ なぜ再現できるか（根拠の数字）＋ 目標到達の見込み。
5. 応答に出る数字（例「西麻布 15分内 72%」「¥2,300/回」）は**すべて実データ**。

### 会話例
```
あなた：あと2万、何時までに稼げる？
AI：今21:47・六本木。同じプレミアム車の人はこの時間
    西麻布→恵比寿で15分内72%乗ってる。あなたも金曜の
    この帯は強い。流せば平均23:30に¥2万到達見込み。
    休憩を挟むなら谷の23時がベスト。

あなた：もう疲れた、早く帰りたい
AI：あと1本で¥28k。渋谷方面に帰りながら拾うと帰路と一致。
    今動けば最短で上がれる。
```

## 4. システム構成（grounded LLM）

**設計原則: 計算は既存ロジック、AIは語りだけ。** これによりAIに数字を捏造させず、再現性と信頼を担保する。

```
「相談」ボタン押下
 └→ 収集: 現在地町名 ＋ 時刻 ＋ 今日の目標/進捗
      └→ 事実エンジン（FactEngine: 大半は既存 chart-helpers の組み替え）が「事実パック」を算出
           ├─ あなたの履歴: この曜日×時間×エリアの傾向（hourlyDowEfficiency 他）
           ├─ 全体匿名プール: 同車種のこの時間エリア効率（k匿名 ≥2）
           ├─ 次の一手候補: nextBoardBreakdown / highValueAreas / stabilityTier
           └─ 目標逆算: 残り¥ / 残り時間 / 必要本数（既存ペースロジック）
      └→ LLM adapter（モデル非依存）に［事実パック ＋ 質問 ＋ 会話履歴］を渡す
           └→ AIは事実パックの値だけを使って会話で返す（数字は計算済みを引用）
```

### コンポーネント（責務とインターフェイス）

| コンポーネント | 責務 | 入力 | 出力 |
|---|---|---|---|
| **DailyGoal** | 今日の目標の保持・進捗計算 | 目標(¥/帰宅時刻)・当日drives | 残り¥/残り時間/必要本数 |
| **ContextCollector** | 相談時の文脈収集 | GPS（現在地→町名・非保存）・時刻・vehicleType | 現在地町名・時刻・車種 |
| **FactEngine** | 事実パックの算出（既存分析関数の組み替え） | 文脈＋ユーザー履歴＋全体プール | 構造化「事実パック」(JSON) |
| **GlobalPoolBatch** | 全体匿名プールの日次事前集計 | 全ユーザーdrives（anon化） | 車種×エリア×時間の効率集計 |
| **LLMAdapter** | 事実パック＋質問→自然言語応答（モデル非依存） | 事実パック・質問・履歴 | 会話テキスト |
| **CoachUI** | チャット画面・プリセットチップ・目標設定 | ユーザー操作 | 表示 |

各コンポーネントは独立してテスト可能。FactEngineの出力（事実パック）は固定スキーマで、LLMAdapterはそれ以外の数値を生成しない（プロンプトで制約＋検証）。

## 5. データ基盤（調査済みの現状）

既存資産で大半をまかなえる（`~/work/taxi-dev` 調査済み）:
- 乗車1件単位の明細（boardTime/alightTime/boardPlace/alightPlace（町名）/amount/km/isPickup/isCancel）
- vehicleType（japantaxi/premium）が各driveとユーザー設定に存在
- グループ匿名集計基盤（group-anon の tripToPoolItem / group-pool-core）
- 既存分析: hourlyDowEfficiency / nextBoardBreakdown / highValueAreas / stabilityTier / ペース予測
- 現在地→町名の逆ジオコーディング（保存しない）

**決定的に足りない**: 乗降地の緯度経度（町名テキストのみ）→ 地図ピンポイント提案はv1対象外（町名粒度で十分）。

## 6. 全体匿名プールのプライバシー

- 既存のanon化（userId除去・エリア町名を粗く・**2人未満は集計を返さない**）を全体に拡張。
- 相談で他者を出す時は必ず「同車種◯人の傾向」と**集団表現のみ**。個人特定は不可能。
- 拠出は**既存の「統合分析オフ」トグルを流用**（オプトアウト式・既定オン）。
- 現在地・GPS座標は保存しない（既存のprivacy by design踏襲）。

## 7. 残りの設計（承認済みの決定）

- **ベテランの「張り」レイヤー**: v1は軽量。AIが時々「いつもの○○に加えて、今日は△△も試せる（同車種の上位者はこう動く）」と“もう一手”を添える口調オプション。本格的な実験モードはv2。
- **置き場所**: ホームに「AIに相談」ボタン＋チャット画面。ツール一覧にも導線。
- **アクセス制限**: フルプラン限定（差別化機能）。既存 access-control.js のゲートを利用。

## 8. v1スコープ（YAGNI）

### 入れる
- 対話「相談」＋プリセットチップ
- 今日の目標設定（¥/帰宅時刻）＋進捗逆算
- 現在地（町名・非保存）連動
- あなた履歴 ＋ 全体匿名プール参照（車種セグメント）
- 再現性の説明つき回答
- FactEngine ＋ モデル非依存 LLMAdapter
- フルプラン限定ゲート

### 入れない（v1対象外）
- 地図ピンポイント提案（座標が無い）
- リアルタイム自動監視・プッシュ通知
- 音声入力／読み上げ
- 配車アプリ・無線連携
- 本格的な実験/張りモード（v2）

## 9. 成功基準

- 相談に対し、**実データ由来の数字**を含む具体的な次の動きと根拠を返せる（数字の捏造ゼロ）。
- 目標（¥/帰宅時刻）と進捗に応じて回答が変わる。
- 車種セグメント（premium/japantaxi）で参照プールが切り替わる。
- ソロユーザー（グループ未加入）でも全体匿名プールの知見が効く。
- 1相談あたりのLLMトークンが小さく、激安モデルで実用品質。

## 10. リスク・留意

- **LLMの数値捏造**: プロンプト制約＋応答後の数値検証（事実パックに無い数字を出していないかチェック）で防ぐ。
- **全体プールの偏り/過疎**: k匿名2人未満は出さない。データが薄いエリア×時間は「あなたの履歴」にフォールバック。
- **コスト暴走**: 事実パックを小さく保つ。必要に応じてレート制限。
- **デプロイ**: バックエンド（事実エンジン/プール集計/LLM中継）は既存worker基盤に載せる想定。dev反映は dpush.sh、本番は v* タグ（既存フロー）。

# ホーム「あなたの数値」— 設定可能な目標/数値ダッシュボード 設計

- 日付: 2026-06-08
- 対象: タクシー日報アプリ ホーム画面の結果表示
- worktree: `~/work/taxi-metrics` / branch `feat/home-configurable-metrics`

## 1. 目的・背景

現状のホーム結果表示は、目標に対する状況が3か所に散っている（ヒーロー／手取り目標カード／「歩率と着地予測」折りたたみ内の総支給対比）。％・税込/税抜・複数バー・折りたたみが多く「いま目標に対してどうなのか」が一目で分からない。

乗務員が **自分の見たい数値だけを選んで並べられる** 設定可能な結果表示にする。あわせて散在していた目標対比を1か所に集約する。

## 2. 最重要の制約（責任出番と公出の分離）

- **1〜11出番＝責任出番**。段階歩率（rateTable）の対象。**責任出番は法律上11が上限**で、12以上はありえない。
- **12出番目以降＝公出（公休出勤）**。固定歩率（`rateTable["12_13rate"]`）の対象。
- すべての数値は **「責任出番(1〜11)」と「公出(12〜)」を必ず別グループで認識・表示** する。両者を合算した値は「月度全体」グループに置く。

## 3. 全体像

ホームに **「あなたの数値」カード** を1枚追加（ヒーロー直下、主要な結果表示として）。中身は乗務員が選んだ数値だけが、3つの固定グループ見出しの下に並ぶ。

- グループは固定3つ・順序固定: **① 責任出番(1〜11) → ② 公出(12〜) → ③ 月度全体**
- 各グループ内に、選択された数値が並ぶ（グループ内の並び順はカタログ定義順。ドラッグ並べ替えは v1 スコープ外）
- カード右上に **「⚙ 数値を選ぶ」** → ピッカー（グループ別チェックリスト）でON/OFF
- 選択は **個人設定**（端末localStorage、既存の設定同期に乗せてFirestoreにも保存）

## 4. 数値カタログ

各数値は `id` を持つ。税込/税抜が両方ある数値は **別々のチェック項目**（片方だけ選べる）。表示時、同じ基底メトリクスの税込と税抜が両方ONなら **1行に並記**（例: `¥92,400 / ¥84,000(税抜)`）。

### グループ① 責任出番(1〜11)
- `resp.sales.total.incl` 11出番までの合計売上（税込）
- `resp.sales.total.excl` 11出番までの合計売上（税抜）
- `resp.sales.avg.incl` 11出番までの平均売上（税込）
- `resp.sales.avg.excl` 11出番までの平均売上（税抜）
- `resp.need.totalRemain.incl` / `.excl` 11出番まで残りで必要な総売上（税込/税抜）
- `resp.need.perShift.incl` / `.excl` 11出番まで残りの1出番あたり・均等（税込/税抜）
- `resp.takehome` 11出番までの手取り（着地）※目標連動（`takeHomeAt11Target`）

### グループ② 公出(12〜)
- `kosyutsu.sales.total.incl` / `.excl` 公出ぶんの合計売上（税込/税抜）
- `kosyutsu.sales.avg.incl` / `.excl` 公出ぶんの平均売上（税込/税抜）
- `kosyutsu.takehome` 公出ぶんの手取り（積み増し・着地）※目標連動（`takeHomeAfter11Target`）

### グループ③ 月度全体
- `month.gross` 月度予想 総支給（着地）※目標連動（`grossTarget`）
- `month.takehome` 月度予想 手取り（着地）※目標連動（`takeHomeTarget`）
- `month.sales.total.incl` / `.excl` 月度合計 営収（税込/税抜）
- `month.rate` 着地歩率

## 5. 目標連動（target-aware）— 決定: 案A

「目標連動」フラグを持つ数値（`resp.takehome` / `kosyutsu.takehome` / `month.gross` / `month.takehome`）は、設定画面の対応する目標額の有無で表示が変わる:

- **目標が設定されている**: 対比表示に格上げ → `目標 / 着地(or 現時点) / あと◯円(差額) / 達成見込・未達見込` ＋ 進捗バー
- **目標が未設定（案A）**: 素の数値（着地額）だけを表示。対比やバーは出さない。

目標フィールドの対応:
| 設定フィールド | 連動する数値 | グループ |
|---|---|---|
| `takeHomeAt11Target` | `resp.takehome` | ① 責任 |
| `takeHomeAfter11Target` | `kosyutsu.takehome` | ② 公出 |
| `grossTarget` | `month.gross` | ③ 全体 |
| `takeHomeTarget` | `month.takehome` | ③ 全体 |

目標を持たない売上系数値（合計/平均/均等/営収）は常に素の数値（案A）。

## 6. 各数値の算出定義

既存の `js/payroll.js` / `requiredUniformSales` / `calcMonthlySales` / breakdown を用いる。乗務配列 `drives`（日付昇順）, `config`, 期間, `takeHomeRate`, 責任出番=11固定, `respShifts=plannedShifts`（カレンダー予定出番）を入力とする。

- **責任出番ぶん drives**: `drives.slice(0, 11)`（11未満ならある分だけ）。
- **公出ぶん drives**: `drives.slice(11)`。
- `resp.sales.total.incl/excl`: 責任ぶり drives の `calcDailySales` 合算（税込=Σamount、税抜=税込/1.1）。
- `resp.sales.avg.*`: 上記 ÷ 責任ぶん出番数（最大11）。
- `kosyutsu.sales.*`: 公出ぶん drives で同様。出番が11以下なら公出グループは「対象なし」表示（または非表示）。
- `resp.need.*` / 均等: 目標（`takeHomeAt11Target` があればそれ、無ければ既存の月度目標ロジックに準拠）に対し、責任出番の残り（=`max(0, 11 - 実出番)`）で `requiredUniformSales` 相当を税込で算出、税抜=÷1.1、総額=均等×残り。**残り出番は責任出番(11)基準で数える**（公出は含めない）。
- `month.gross` 着地: `predicted.total`（既存 predictMonthly。責任11段階＋公出固定を正しく含む。v1.76.0 で着地=predicted.total に統一済）。
- `month.takehome` 着地: `predicted.total × takeHomeRate`。
- `resp.takehome` 着地: 責任ぶん basePay（breakdown の `basePay11` or `basePay`）× `takeHomeRate`。
- `kosyutsu.takehome` 着地: 公出ぶん積み増し（breakdown `extraTotal`）× `takeHomeRate`。12出番以上に到達する月のみ。
- `month.rate` 着地歩率: 既存 `currentTier.rate`（責任出番11基準のティア）。

> 注: 既存の `requiredUniformSales` は月度目標を全予定出番で達成する均等売上を返す。責任出番(11)基準の「残り必要」を出すため、対象出番数と目標の取り扱いを実装時に明確化する（実装プランで詳細化）。

## 7. 既存表示の整理（重複解消）

新「あなたの数値」カードに目標対比を集約し、重複を除去する:

- **削除/統合**: スタンドアロンの「手取り目標」カード（`targetCard`, index.html L700+）と、「歩率と着地予測」折りたたみ内の「あなたの目標との対比」（`renderTargetCard`）の **目標対比表示**は新カードへ集約。
- **維持**: ヒーロー（現時点手取り/総支給/月度予想手取り）、「給与の内訳」「営収・1出番平均」「歩率と着地予測（歩率マップ・着地フロー）」の各折りたたみは **詳細情報として残す**（目標対比の重複部分のみ新カードへ移す）。
- 「あと必要な売上」も新カードの責任出番グループ（均等・残り総額）に集約。

## 8. 永続化 / データモデル

- `config.homeMetrics`: `{ selected: string[] }`（選択された数値 id の配列。順序はカタログ定義順で表示するため保存不要だが、将来の並べ替え用に配列で保持）。
- 個人設定（company-level ではない）。`js/default-config.js` に既定の選択セットを定義。
- 既定の選択（初回）: `resp.sales.total.incl`, `resp.sales.avg.incl`, `resp.need.perShift.incl`, `resp.need.perShift.excl`, `month.gross`, `month.takehome`（目標があれば対比に自動格上げ）。
- localStorage 正本＋既存の設定同期経路でFirestoreへ（既存パターン踏襲）。

## 9. UI / インタラクション

- 「あなたの数値」カード: グループ見出し（色分け: 責任=青系 / 公出=紫系 / 全体=緑系）＋選択数値の行。
- 「⚙ 数値を選ぶ」: モーダル or 展開パネル。3グループのチェックリスト。ON/OFF即反映。
- 数値1行のフォーマット:
  - 素の数値: `ラベル` ＋ `¥金額`（税込/税抜両方ONなら `¥A / ¥B(税抜)`）。
  - 目標連動(対比): `ラベル ✓達成見込/未達見込` ＋ `目標¥X / 着地¥Y / +¥Z(or あと¥Z)` ＋ 進捗バー（実績/予想）。
- 専門用語・裏側ロジックは出さない（既存ルール踏襲: 手法名/しきい値/係数を表示しない）。

## 10. テスト

- 単体: 各数値の算出関数（責任/公出 分離、税込/税抜、均等、目標連動の有無）を `tests/` に追加。責任出番11境界、公出0件、出番0件、目標未設定/設定済みの分岐を網羅。
- 既存 `payroll.test.js` を壊さない（算出は payroll の純関数を再利用）。
- スモーク: dev実機（kimi-webbridge / 実アカウント）で、選択ON/OFF→表示反映、目標設定→対比格上げ、を確認。

## 11. スコープ外（YAGNI / v2以降）

- グループ内のドラッグ並べ替え（v1はカタログ定義順）。
- プリセット（売上重視/手取り重視）。
- 日商・時間あたりなど新規メトリクスの追加（カタログは将来拡張可能な設計にとどめる）。
- 完全自由な目標の自作（ラベル＋金額＋期間）。

## 12. 受け入れ基準

1. 責任出番(1〜11)と公出(12〜)が常に別グループで表示され、混ざらない。
2. 「11出番までの合計売上・平均売上（税込/税抜）」が選べて正しい値で出る。
3. 「残り(責任11まで)で必要な総売上・1出番あたり均等（税込/税抜）」が選べて出る。
4. 設定で目標額があれば対比（目標/着地/あと◯円/達成見込）に格上げ、無ければ素の数値（案A）。
5. 選択がlocalStorage＋Firestoreに保存され、再訪時も維持。
6. 既存の目標対比の重複表示が解消され、目標まわりが1か所に集約される。

# ステージ制お手本（目標売上ステージ別の稼ぎ方ヒートマップ）設計

**作成日**: 2026-05-22
**対象**: タクシー日報PWA（cabis）— `review.html`（自分データの分析画面）
**関連**: `2026-05-22-heatmap-meaning-layer-design.md`（塊①・本番反映済 v1.20.0）。本仕様は塊③。
**前提**: 自分（本人）の約2年分データを使う自己学習機能。他の乗務員／みんな版はスコープ外（将来）。

---

## 1. 背景・狙い

塊①で「いつ走って・いつ休むか（時給の意味づけ）」は出した。塊③は一段上の問い「**目標の売上を達成する日は、どう動いているか**」に答える。

本人の発案: 1日の売上をステージ（5千円刻み）に分け、目標ステージを選ぶと「その売上だった日々の曜日×時間の稼ぎ方」が見える。**目標から逆算する地図**。中央値（典型）より「なりたい自分の再現」に近い。

本人データは売上の幅が広い（昔は5万の日もあった／今は12万級の日もある）ので、自分の歴史だけでステージが埋まる＝他者データを待たずに成立（コールドスタート回避）。

---

## 2. ゴール

1. 本人の各日を「1日の税込メーター営収」でステージ分けし、選んだステージの日々の **曜日×時間 平均売上ヒートマップ** を表示する。
2. 「6.5万の日は夕方〜夜が厚い」のように、目標達成日の稼ぎ方の型が一目で分かる。
3. 既存の分析画面（review.html）に新カードとして自然に収まる。

## 4. 設計

### 4.1 ステージ定義

- 各日の **日次売上** = その日の `trips` のうち `!isCancel` の `amount` 合計（`rankDrivesBySales` と同一定義）。`isSummaryOnly` の日は除外。
- ステージ（5千円刻み）:
  - `〜5万`（50000未満を1つにまとめる）
  - `5.0–5.5` / `5.5–6.0` / `6.0–6.5` / `6.5–7.0` / `7.0–7.5` / `7.5–8.0` / `8.0–8.5` / `8.5–9.0` / `9.0–9.5` / `9.5–10.0` / `10.0–10.5` / `10.5–11.0` / `11.0–11.5` / `11.5–12.0`（万円）
  - `12万+`（120000以上を1つにまとめる）
- 区切り規則: 下限以上・上限未満（例 6.0–6.5万 = 60000以上65000未満）。
- **該当日数が1日以上あるステージのみ表示**。空ステージは出さない。

### 4.2 ステージ選択UI

- カード上部に各ステージの **チップ**（範囲＋該当日数）。例: `6.0–6.5万 (23日)`。
- 1つ選択 → 下にヒートマップ描画。
- 初期選択 = **該当日数が最多のステージ**（最も信頼できる＝まず見せる価値が高い）。

### 4.3 ヒートマップ（曜日×時間の平均売上）

- セル(dow, hour) = **平均売上** = （そのステージの「dowの日々」の hour帯売上の合計）÷（そのdowの該当日数）。
  - 「hour帯売上」は既存 `hourlyDowEfficiency` のtrip按分ロジック（trip amountを時間帯重なりで按分）を流用して算出。
- 色の濃淡 = 平均売上の高低（既存ヒートマップの色スケール流用、max正規化）。
- **サンプル不足**: あるdowの該当日数 < 3 のときは、そのdow列のセルをグレー表示（薄いデータと分かるように）。
- セルタップ詳細: 「{曜日} {hour}時台・平均売上 ¥X・該当{そのdowの日数}日・平均{件数}件」。

### 4.4 純ロジック（`js/chart-helpers.js` に追加・テスト必須）

- `dailySalesList(drives)` → `[{date, sales, dow}]`（非summary・sales>0）。`rankDrivesBySales` と同じ売上定義を共通化（重複ロジックを1関数に寄せる）。
- `salesStages(drives, opts={min:50000, max:120000, step:5000})` → 該当日数1以上のステージ配列 `[{key, lower, upper, label, dates:[...], count}]`（`〜5万` と `12万+` の端は特別バケット）。
- `stageHeatmap(stageDrives)` → `{ matrix, dowDayCount }`。`matrix[dow][h].avgSales`、`dowDayCount[dow]`（そのステージのdow別日数）。実装は `hourlyDowEfficiency(stageDrives)` を流用し、`avgSales = cell.sales / dowDayCount[dow]`（0除算は0）。**既存 `hourlyDowEfficiency` は無変更**。

### 4.5 描画（review.html）

- 新 `<section>`「目標ステージ別の稼ぎ方」。
- `renderStageBenchmark()`:
  1. `salesStages(allDrives)` で全期間のステージ＋日数を出しチップ描画
  2. 選択ステージの `stageDrives`（そのステージの日付の drives）で `stageHeatmap` → セル描画（既存ヒートマップのCSS/色/タップ流用、指標は平均売上）
- 車種フィルタ（既存）適用後の `allDrives` を入力にする（自分データ）。

## 6. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 高ステージは日数が少なくヒートマップが薄い | 誤誘導 | dow<3日グレー＋ステージチップに日数明示。初期は最多ステージ |
| 古い日（昔の低営収日）が混じる | 行動が今と乖離 | 本人合意で全期間固定。将来、期間フィルタ検討（本仕様外） |
| 平均売上の按分が既存と不一致 | 数値ズレ | `hourlyDowEfficiency`のsales按分を流用し一貫させる |
| review.html肥大 | 保守性 | 純ロジックはchart-helpersに分離。描画は新関数1つに閉じる |

## 8. オープン論点（レビューで決める）

- **論点A**: 平均売上の分母を「そのdowの該当日数」にする（採用）か、「そのセルに稼働があった日数」にするか。採用案＝該当日数（走ってない時間帯は平均が下がる＝リアル）。
- **論点B**: 初期選択ステージ＝最多日数（採用）か、最高ステージ（憧れ）か。
- **論点C**: 平均売上の表示単位（円そのまま／百円丸め）。塊①に合わせ百円丸め推奨。
